# Edits to upstream `core/`

Kept to a minimum so upstream merges stay small. Everything else lives in `studio/`.

| File                                                                                                             | Change                                                                                                                                                                               | Why                                                                                                                                                                                  |
| ---------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `frontend/src/editor/core/components/viewer/BookmarkSidebar.tsx`                                                 | "Add bookmark" calls `replaceTableOfContents()` from `@editor/services/tableOfContentsService` instead of posting to the Java backend                                                | The studio build shadows that service with a pdf-lib writer (`studio/services/tableOfContentsService.ts`); core keeps the backend version                                            |
| `frontend/src/editor/core/services/tableOfContentsService.ts`                                                    | New: the backend-calling implementation behind that seam                                                                                                                             | Same                                                                                                                                                                                 |
| `frontend/src/editor/core/components/shared/FileSidebar.tsx`, `FileSidebarFileItem.tsx` (+ css, tests)           | The library list is a plain recent list: no checkmark, a click opens the file in the viewer. In Active Files and Page Editor the list is replaced by an Add from recent files button | The checkmark meant "loaded in the workbench", which tools never use as a selection, so it read as a broken multi-select                                                             |
| `frontend/src/editor/core/components/shared/AddFromRecentModal.tsx`                                              | New: multi-select dialog that adds library files to the workbench                                                                                                                    | Replaces the sidebar list in editor views                                                                                                                                            |
| `frontend/public/locales/en-US/translation.toml`                                                                 | Removed keys for deleted tools; added `fileSidebar.recentPicker.*` and four `annotation.*` keys                                                                                      | The unused and missing translation tests                                                                                                                                             |
| `frontend/src/editor/core/**/*.test.*` (HomePage.startupView, useUrlSync.transitions, notificationRetry, others) | Tests rewritten around live tools or trimmed; tests of removed tools deleted                                                                                                         | Their subjects were removed with the Java backend                                                                                                                                    |
| `frontend/src/editor/core/contexts/ToolWorkflowContext.tsx`                                                      | `setReaderMode(true)` goes through `requestNavigation` and `restoreWorkbench("viewer")`, so reader mode only turns on after the unsaved-changes prompt is settled                    | Before, the Reader rail button turned reader mode on while the prompt was open; cancelling left the page editor in a half-switched state. Covered by `HomePage.startupView.test.tsx` |
| `frontend/src/editor/core/components/viewer/ViewerTilingLayer.tsx` (new, + test), `LocalEmbedPDF.tsx` | Page tiles render through our own layer instead of EmbedPDF's `TilingLayer`: tiles from the previous zoom stay until every tile at the new zoom has decoded | EmbedPDF dropped the old tiles before the new `<img>`s decoded, and after any partial step during fast zooming, so the blurry page preview flashed through |
| `frontend/src/editor/core/components/viewer/useViewerWheelZoom.ts` (new, + test), `EmbedPdfViewer.tsx`, `ZoomAPIBridge.tsx`, `contexts/viewer/viewerBridges.ts`, `viewerActions.ts`, `viewerStoryProviders.tsx` | Ctrl+wheel zooms about the pointer through a new `zoomBy(factor, center)` on the zoom API, committed with `flushSync` | The plugin's `zoomIn`/`zoomOut` anchor on the viewport centre, so the spot under the cursor drifted away, worst when zooming out |
| `frontend/src/editor/core/components/viewer/ZoomAPIBridge.tsx` | Requests the first fit-width itself as soon as the document is ready | The plugin's own first fit runs before the viewport has a size and is retried only by a 150 ms debounced resize; the viewport stays blank until then |
| `frontend/src/editor/core/hooks/useFontFallbackConfig.ts` | System-font lookup starts on import, is cached per app run, and an empty result never replaces the config | A config change rebuilds the PDFium engine, so every document open built the worker and WASM twice |
| `frontend/src/editor/core/hooks/useLocalPdfiumEngine.ts` (+ test) | An unmounted viewer's engine is kept and handed to the next viewer with equal options (compared by value); one engine is kept at most | `LocalEmbedPDF` remounts per document, so each open paid for a new worker and WASM boot. The registry closes its own documents on teardown, so the kept engine holds none |
